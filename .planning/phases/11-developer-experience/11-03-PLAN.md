Create `docs/agents.md` as a comprehensive agent system reference. Per CONTEXT.md: "complete enough for an AI agent to autonomously create, configure, and validate agents."

**Structure (heading hierarchy is Claude's discretion per CONTEXT.md):**

**1. Overview**
- What agents are: directories with manifest.yaml + prompts/ containing .md files
- How they run: AgentEngine loads manifest, executes beads in sequence, each bead is a `claude -p` invocation
- Directory structure: `agents/<name>/manifest.yaml`, `agents/<name>/prompts/*.md`

**2. Quick Start / End-to-End Walkthrough**
- Create agent: `nightshift agent init my-agent`
- Edit prompts: modify files in `agents/my-agent/prompts/`
- Configure: set variables in `nightshift.yaml`
- Validate: `nightshift agent validate my-agent`
- Test: `nightshift run --agent my-agent`
- Schedule: add cron entry in `nightshift.yaml`

**3. Manifest Reference**
Document EVERY field from ManifestSchema with type, default value, and example. Use code-agent's manifest.yaml as the running example for each field.

Fields:
- `name` (string, required): Agent identifier, kebab-case
- `description` (string, required): Human-readable description
- `model` (string, optional, default: "claude-sonnet-4-20250514"): Default model for all beads
- `timeout` (string, optional, default: "15m"): Default timeout for all beads
- `allowedTools` (string[], optional, default: ["Bash", "Read", "Write"]): Default tools for all beads
- `env` (array, optional): Agent-level env vars (passthrough strings or {name, value} objects)
- `variables` (Record<string, string>, optional): Template variables with default values
- `preamble` (string, optional): Path to preamble prompt prepended to all beads
- `beads` (array, required): Ordered list of pipeline stages

**4. Bead Reference**
Document each bead field. Explain the two bead types:
- `standard`: Runs `claude -p` with the prompt. Most common type.
- `git-clone`: Clones a repository. Uses GitCloneBeadPlugin. Output provides repoDir and handoffDir.

Bead fields:
- `name` (string, required): Unique within the manifest
- `type` (string, required): "standard" or "git-clone"
- `prompt` (string, required): Relative path to prompt .md file
- `model` (string, optional): Overrides agent-level model
- `timeout` (string, optional): Overrides agent-level timeout
- `allowedTools` (string[], optional): Replaces (not merges) agent-level tools
- `env` (array, optional): Merged with agent-level env (bead wins on collision)
- `outputSchema` (JSON Schema object, required): Schema for bead's JSON output. Compiled to Zod at load time via `z.fromJSONSchema()`.
- `mcpConfig` (string, optional): Path to MCP config JSON file. Supports template variables.
- `retry` (object, optional): `{ maxAttempts: number, retryFrom: string }`. Retries from the named bead.

Show code-agent example: "Here's how code-agent declares its verify bead with retry from implement..."

**5. Template Variable System**
- Syntax: `{{variable_name}}` in prompt files
- Dot notation: `{{beads.clone.output.repoDir}}` for accessing bead outputs
- Built-in variables (always available, highest precedence): `task_id`, `run_date`, `agent_name`, `repo_path`
- User-defined variables: declared in manifest `variables:` section with defaults, overridden in `nightshift.yaml` schedule entry `variables:`
- Bead output references: `{{beads.<bead_name>.output.<field>}}` and `{{beads.<bead_name>.rawOutput}}`
- Resolution precedence: built-ins > config overrides (nightshift.yaml) > manifest defaults
- beads.* references are only resolved at runtime (skipped during load-time validation)

Show code-agent example: "Here's how code-agent's implement.md references the analyze bead's output..."

**6. nightshift.yaml Configuration**
- `agents:` array: declare agents by name with optional variables and fallback categories
- `schedule:` array: cron entries referencing agents with variable overrides
- `agents_dir:` path to agents directory (default: ./agents)
- Example with code-agent configured

**7. Output Schema and Contracts**
- Every bead must declare `outputSchema` as JSON Schema
- Bead output must be a JSON code block (```json ... ```) in the claude -p response
- Engine extracts last JSON code block and validates against compiled schema
- Contract violation = pipeline abort (BEAD_CONTRACT_VIOLATION error)
- Show example outputSchema and matching JSON output

**8. Environment Variables**
- Two forms: passthrough string ("GITLAB_TOKEN") reads from host, explicit {name, value} for hardcoded
- Agent-level env merged with bead-level env (bead wins on collision)
- Security: minimal safe env injected (HOME, PATH, USER, LANG, SHELL, TERM) -- everything else blocked unless declared
- Secret-looking names with hardcoded values produce a warning

**9. CLI Commands Reference**
- `nightshift agent init <name> [--force]`
- `nightshift agent validate <name|path>`
- `nightshift agent list [--json]`
- `nightshift agent show <name>`
- `nightshift run --agent <name>`

Full annotated walkthrough of `agents/code-agent/manifest.yaml`. Each section of the manifest explained in context: why code-agent uses opus for analysis, why verify retries from implement, why GITLAB_TOKEN is only on clone and mr beads, how category rotation works via variables, etc.

**Tone:** Technical reference. No marketing language. Precise. Every claim backed by how the system actually works.
